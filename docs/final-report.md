# Hermes Agent 模型选择推荐报告

> 汇总时间：2026-05-27
> 数据来源：T1 能力维度调研 → T3 权重体系设计 → T4 权重审视 → T2 实测成绩搜集
> 候选模型：GLM-5.1、GLM-5-Turbo、DeepSeek-V4-Flash、DeepSeek-V4-Pro

---

## 一、评估方法论

### 1.1 九大能力维度

基于 T1 调研，将模型能力拆解为 9 个维度：

| 编号 | 维度 | 代表评测集 |
|------|------|-----------|
| D1 | 综合能力 | MMLU, MMLU-Pro, C-Eval, CMMLU |
| D2 | 编程 | HumanEval, LiveCodeBench, SWE-Bench |
| D3 | 数学推理 | MATH, GSM8K, AIME |
| D4 | 科学推理 | GPQA Diamond, ARC-Challenge |
| D5 | 长文本 | LongBench-V2, Needle-in-Haystack |
| D6 | 指令遵循 | IFEval, AlpacaEval 2.0 |
| D7 | 工具调用/Agent | AgentBench, BFCL, Toolathlon |
| D8 | 中文理解 | C-Eval, CMMLU, BenchLM Knowledge |
| D9 | 多轮对话 | Arena Elo, MT-Bench |

### 1.2 六个 Profile 及权重分配

T3 为 6 个 Agent Profile 分别设计了维度权重：

| 能力维度 | Coder | Planner | Writer | Researcher | Reviewer | Doubter |
|----------|-------|---------|--------|------------|----------|---------|
| D1 综合能力 | 15% | **25%** | 20% | 20% | 20% | 20% |
| D2 编程 | **30%** | 8% | 5% | 2% | **25%** | 5% |
| D3 数学推理 | 5% | 10% | 5% | 8% | 10% | **20%** |
| D4 科学推理 | 3% | 5% | 3% | 10% | 10% | **20%** |
| D5 长文本 | 1% | 2% | **15%** | **15%** | 3% | 4% |
| D6 指令遵循 | 15% | **20%** | 15% | 5% | 15% | 10% |
| D7 工具调用 | **20%** | 15% | 2% | **25%** | 5% | 8% |
| D8 中文理解 | 10% | 10% | **25%** | 10% | 10% | 10% |
| D9 多轮对话 | 1% | 5% | 10% | 5% | 2% | 3% |

> T4 审视指出：评测集跨维度重叠（如 C-Eval 同时计入 D1 和 D8）可能导致重复计分，且缺少安全性/创造力量度。本报告在现有体系下计算，但标注了局限性。

### 1.3 计算方法

- 每个维度选取该模型最佳可用分数（优先 BenchLM 聚合分 > 单项高分）
- 缺失数据的维度在计算时跳过，权重归一化到已有数据的维度上
- 最终得分为：Σ(维度分 × 权重) / Σ(有效权重) × 100%

## 四、推荐结论

### 4.1 总览：Profile × 模型推荐矩阵

| Profile | Best | Runner-up | 分差 | 稳健性 |
|---------|------|-----------|------|--------|
| **Coder** | DS-V4-Pro (84.5) | GLM-5.1 (84.1) | 0.4 | ⚠️ 可互换 |
| **Planner** | GLM-5.1 (84.7) | DS-V4-Pro (84.5) | 0.2 | ⚠️ 可互换 |
| **Writer** | GLM-5.1 (82.0) | DS-V4-Pro (77.0) | **5.0** | ✅ 显著领先 |
| **Researcher** | GLM-5.1 (80.8) | DS-V4-Pro (78.4) | 2.3 | ⚠️ 可互换 |
| **Reviewer** | DS-V4-Pro (86.1) | GLM-5.1 (84.6) | 1.5 | ⚠️ 可互换 |
| **Doubter** | DS-V4-Pro (85.8) | GLM-5.1 (84.8) | 0.9 | ⚠️ 可互换 |

### 4.2 关键发现

1. **GLM-5.1 和 DS-V4-Pro 双雄并立**：在几乎所有 Profile 中，这两个模型互为 Best / Runner-up，且分差普遍在 0.2-2.5 分之间。唯一例外是 **Writer**（GLM-5.1 领先 5 分）。

2. **GLM-5.1 的核心优势：数据完整性**。它是唯一一个 9 个维度全部有数据的模型，BenchLM 提供了全面的类别级聚合分。这既是优势（结果更可信），也是局限（无法验证其单项能力细节）。

3. **DS-V4-Pro 的核心优势：上限更高**。在有数据的维度上，DS-V4-Pro 在 D1(89.7 vs 82.0)、D2(89.5 vs 83.4)、D3(92.4 vs 89.7)、D4(90.1 vs 86.2) 上均领先 GLM-5.1。缺失的 D6 和 D9 恰恰是 GLM-5.1 最强的维度（D6=91.7，D9=82.0），如果补充这两个维度的数据，DS-V4-Pro 的排名可能会进一步上升或保持。

4. **DS-V4-Flash 全面落后**：在所有 Profile 中均排名第三，与领先者差距 5-12 分。适合对成本敏感但不追求极致性能的场景。

5. **GLM-5-Turbo 无法评估**：公开评测数据几乎为零（仅有 Arena Elo 1456），无法纳入任何可靠排名。

## 五、敏感性分析

### 5.1 方法

对每个维度权重进行 ±10 个百分点的扰动（重新归一化后计算），检查 Best/Runner-up 排名是否翻转。

### 5.2 结果

| Profile | 排名翻转次数 / 总测试数 | 翻转条件 |
|---------|----------------------|----------|
| Coder | **6/18** | D1/D2 降低或 D5/D6/D7/D8 提升时，GLM-5.1 超越 DS-V4-Pro |
| Planner | **10/18** | 任何维度扰动都可能翻转（分差仅 0.2），DS-V4-Pro 在 D1-D4 提升时领先 |
| Writer | **2/18** | D5 或 D9 降低时 Turbo 被 Pro 替代（GLM-5.1 始终领先） |
| Researcher | **4/18** | D3 降低或 D5 提升时 Turbo 跃升（数据不足导致排名不稳定） |
| Reviewer | **2/18** | D5 提升或 D9 降低时翻转 |
| Doubter | **3/18** | D5 提升或 D8/D9 扰动时翻转 |

### 5.3 解读

- **Planner 最不稳定**（56% 翻转率）：GLM-5.1 与 DS-V4-Pro 仅差 0.2 分，任何权重调整都可能改变结论。这说明 Planner 场景下两模型几乎等价。
- **Writer 最稳定**：GLM-5.1 以 5 分优势领先，所有扰动下仍保持第一。
- **Coder 较敏感**：分差 0.4 分，但翻转主要发生在 GLM-5.1 强项（D6 指令遵循 91.7）权重提升时。如果 DS-V4-Pro 的 IFEval/AlpacaEval 数据公布且表现良好，排名可能稳定为 DS-V4-Pro 胜出。

## 六、数据缺失说明与影响评估

### 6.1 GLM-5-Turbo（严重缺失 — 无法评估）

- 仅 Arena Elo 1456 一个有效数据点
- 作为闭源模型，官方未公开详细评测报告
- BenchLM 上 17/221 评测有数据，不足以产生任何类别排名
- **影响**：完全无法纳入模型选择决策。如需评估，建议申请 API 进行实际任务测试。

### 6.2 DS-V4 系列（缺失 D6 指令遵循、D9 多轮对话）

- 两个模型均缺失 IFEval、AlpacaEval 2.0、MT-Bench、Arena Elo 数据
- **影响**：D6（指令遵循）对 Coder/Planner/Writer/Reviewer 权重为 15-20%，D9 对 Writer 权重为 10%
- 如果 DS-V4-Pro 在 D6 上的表现达到行业平均（~80），则在 Coder 场景下其总分将从 84.5 上升至约 85.0，进一步拉开与 GLM-5.1 的差距
- 如果 DS-V4-Pro 在 D6 上表现不佳（~70），则在 Planner 场景下总分可能降至 82.0 以下，GLM-5.1 将拉开差距

### 6.3 GLM-5.1（数据最完整，但有隐藏局限）

- BenchLM 提供类别级聚合分（如 Coding 83.4），但未公开各评测集单项分数
- 无法确认其在 HumanEval、LiveCodeBench、SWE-Bench 等具体编程评测集上的表现
- D8 中文理解使用 BenchLM Knowledge (84.4) 作为代理，而非 C-Eval/CMMLU 单项分

### 6.4 DS-V4-Flash D8 中文理解为估算值

- 无直接 C-Eval/CMMLU 成绩
- 估算为 70.0（基于 MMLU 82.1 和通用中文能力推算）
- DeepSeek 系列模型中文能力一般较强，实际分数可能高于估算

## 七、T4 审视意见对结论的影响

T4（Doubter 权重审视）提出了 3 个 blocking 问题，以下分析其对最终排名的影响：

| T4 问题 | 对排名的影响 |
|----------|-------------|
| 评测集跨维度重叠（C-Eval→D1+D8） | 会放大 GLM-5.1 在 Writer（D1=20%+D8=25%）上的优势，因为中文能力被双重计算。但 GLM-5.1 的 D8 来源是 BenchLM Knowledge（英文评测集为主），实际重叠影响有限。 |
| 缺少安全性/对齐维度 | 主要影响 Reviewer 和 Doubter。新增安全维度后，由于 DS-V4-Pro 在代码能力上领先，预计 Reviewer 排名不变或 DS-V4-Pro 进一步拉开差距。 |
| 缺少创造力量度 | 主要影响 Writer。GLM-5.1 已在 Writer 上显著领先 5 分，创造力评测可能进一步巩固其优势（GLM-5.1 的 Arena Elo 和指令遵循暗示其生成质量较好）。 |

**结论**：T4 的 blocking 问题不会改变 Best/Runner-up 的基本格局（GLM-5.1 vs DS-V4-Pro），但会增加排名的不确定性区间。

## 八、最终建议

### 8.1 推荐配置方案

| Profile | 推荐模型 | 理由 |
|---------|---------|------|
| **Coder** | DS-V4-Pro | 编程能力最强（LiveCodeBench 93.5, Codeforces 3206, HumanEval 85.2），且 Agent 能力优秀 |
| **Planner** | GLM-5.1 | 数据完整可信（100% 覆盖），综合能力和指令遵循（91.7）在规划场景中至关重要 |
| **Writer** | **GLM-5.1** | 唯一一个显著领先的场景（+5 分），中文理解和指令遵循能力突出 |
| **Researcher** | GLM-5.1 | 数据完整（100% 覆盖），Agent 能力 80.4 + 长文本处理 + 综合能力均衡 |
| **Reviewer** | DS-V4-Pro | 编程和科学推理能力最强，适合代码审查（HumanEval 85.2 + GPQA 90.1） |
| **Doubter** | DS-V4-Pro | 数学推理 + 科学推理双维度最强（GSM8K 92.4 + GPQA 90.1），逻辑审视场景适配 |

### 8.2 成本考量

| 模型 | 参数规模 | 激活参数 | 许可证 | 成本级别 |
|------|---------|---------|--------|---------|
| GLM-5.1 | 7450 亿 (MoE) | 440 亿 | Open Weight | 中高（需 440B 显存，建议 API 调用） |
| DS-V4-Pro | 1.6 万亿 (MoE) | 490 亿 | MIT | 高（需 490B 显存，建议 API 调用） |
| DS-V4-Flash | 2840 亿 (MoE) | 130 亿 | MIT | 低（130 亿激活，可能本地部署） |
| GLM-5-Turbo | 未公开 | 未公开 | 闭源 | 按量付费 |

**服务器约束提醒**：当前服务器仅 3.8GB RAM，无 GPU。所有模型均需通过 API 调用，本地部署不现实。API 成本差异主要取决于 token 用量，DS-V4-Flash 的 130 亿激活参数意味着更低的推理成本。

### 8.3 实际部署建议

1. **高优先级**：Writer 用 GLM-5.1（唯一显著领先的场景），Coder/Reviewer/Doubter 用 DS-V4-Pro
2. **灵活配置**：Planner 和 Researcher 两模型差距不大，可根据 API 可用性、延迟、成本灵活切换
3. **备用方案**：DS-V4-Flash 虽然排名靠后，但作为低成本选项，适合对性能要求不高的辅助任务
4. **GLM-5-Turbo 暂不推荐**：在公开数据不足的情况下，无法做出可靠判断，建议等待更多评测数据或自行做实际任务测试

### 8.4 待办事项

- [ ] 获取 DS-V4-Pro 的 IFEval/AlpacaEval 2.0 成绩（补全 D6 维度），这将显著提升排名可靠性
- [ ] 获取各模型的中文学术评测（C-Eval/CMMLU）单项分数，替代当前的代理估算
- [ ] 针对安全性维度（CyberSecEval/HarmBench）补充数据，特别是 Reviewer 和 Doubter 场景
- [ ] 如可能，对 GLM-5-Turbo 进行实际任务测试（写日报、审查 PR、拆分任务），以补全数据缺失
